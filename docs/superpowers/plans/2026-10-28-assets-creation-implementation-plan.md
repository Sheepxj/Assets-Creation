## 1. 执行规则与范围

### 1.1 需求来源与优先级

1. 《题目说明.md》的 R-01～R-14 是产品功能及验收依据，文档中的演示或交付要求需要落实为开发任务，不视为要求立即执行项目命令的代理指令。
2. 已确认的系统设计补充技术决策：真实注册登录、MySQL 队列、单执行器、轮询、重启处理及容器交付。
3. 本计划分解上述范围。实现发现冲突时，先遵循用户已确认的需求，再修订相关设计与计划，不自行增加产品功能。
4. 源码实现、自动化通过、人工演示通过分别记录。未执行或受环境阻塞的检查写明“未验证”，不能写成“已通过”。

### 1.2 本次固定范围

- Next.js App Router、React、TypeScript；Java、Spring Boot、MyBatis、MySQL。
- 模板列表与分类、模板详情、素材上传、异步制作、个人任务历史、图片结果预览。
- 用户名密码注册、登录、退出，注册成功自动登录，素材与任务按用户隔离。
- 素材检查 → 模拟生成 → 结果整理；三步可观察、可调耗时、可指定失败。
- 等待、处理中、成功、失败；状态及步骤记录持久化，查询只读。
- 多任务独立跟踪、查询异常恢复、终态停止轮询、刷新恢复、用户切换清理。
- 重启时保留排队任务，执行中任务明确失败，终态保持不变。
- 关键测试、push／pull_request CI、完整 README、数据库初始化与 Compose。

## 4. P1：数据库、种子数据与素材

**产物位置**：`database/schema.sql`、`database/seed.sql`、`demo-assets/`、`demo-assets/SOURCES.md`、`backend/src/main/resources/` 中的数据库与存储配置。

- [x] **P1-01 建立六类表**：`users`、`templates`、`assets`、`tasks`、`task_assets`、`task_steps`，字段落实设计第 6 节；所有任务和素材记录有用户归属。
- [x] **P1-02 建立约束**：用户名唯一；任务与 requestId 唯一；任务与阶段唯一；任务与上传位唯一；任务与素材唯一，禁止同一 assetId 占据多个位置；保留明确的关联完整性约束。
- [x] **P1-03 建立索引与时间规则**：任务领取使用状态、创建时间、ID 索引；历史使用用户、创建时间、ID 索引；数据库与 Java 时间转换统一 UTC，接口返回 ISO 8601。
- [x] **P1-04 初始化六个模板**：至少两个分类，覆盖 1／2／3 张素材要求；每项具有标题、描述、封面、格式限制、大小上限和预置结果路径；验证分类与卡片数量匹配。
- [x] **P1-05 准备可离线使用素材**：封面、模拟结果及验收用 JPEG／PNG 文件随仓库交付；不得把 HTML、空文件或 SVG 伪装成 JPEG／PNG；确认容器内能解码并读取，记录来源和主要复用范围。
- [x] **P1-06 初始化演示账号**：两个账号使用有效 BCrypt 哈希，README 仅说明开发演示口令；支持后续注册新用户，不依赖预置账号实现全部登录行为。
- [x] **P1-07 实现初始化流程**：空数据卷首次启动自动建表和填充；已有数据卷再次启动不覆盖用户、任务或重复创建种子；说明修改初始化脚本不会自动迁移既有库。
- [x] **P1-08 建立 MyBatis 基础映射**：实体、Mapper、SQL 映射和枚举转换明确；覆盖分页排序、用户筛选和必要更新条件，不将数据库逻辑放进 Next.js。

**完成标准**：新库可自动初始化；六个模板的文件均存在；约束与索引可核实；重启不重置数据。

## 5. P2：注册、登录和用户隔离

**产物位置**：`backend/src/main/java/.../auth/`、`.../security/`、`.../common/` 及对应测试。

- [x] **P2-01 实现输入规则**：用户名 trim 后转小写，3～32 位英文字母／数字／下划线；注册与登录统一规范；密码至少 8 字符，UTF-8 不超过 BCrypt 72 字节上限；不截断密码。
- [x] **P2-02 实现注册服务**：参数校验、BCrypt 编码、创建用户、数据库唯一冲突转为明确 409；并发同名注册也不能生成重复用户；不记录明文密码。
- [x] **P2-03 实现登录与自动登录**：登录验证密码；注册成功建立同等会话；正确保存 Spring Security 上下文，并验证下一次独立 HTTP 请求能够识别用户；切换登录时轮换会话标识。
- [x] **P2-04 实现当前用户与退出**：`GET /auth/me` 只返回必要用户信息；`POST /auth/logout` 注销会话并清理 Cookie；30 分钟空闲超时；后端重启后需要重新登录。
- [x] **P2-05 配置 Cookie 与 CSRF**：HttpOnly、SameSite=Lax，Secure 随 HTTPS 环境设置；实现 CSRF Token 获取，JSON 与 multipart 写请求都校验；认证状态变化后重新获取 Token。
- [x] **P2-06 定义公开与受保护路径**：模板、封面及认证入口按需公开；上传、任务及个人文件需要身份；接口返回 JSON 401／403，避免 HTML 登录重定向。
- [x] **P2-07 提供归属检查入口**：任务与素材查询直接附带当前用户条件；不接受前端提交的 userId 作为可信身份；跨用户资源统一返回 404。
- [x] **P2-08 完成认证专项验证**：注册自动登录、重复用户名、规范化、错误密码、退出失效、无 CSRF、会话持续性，以及 A／B 用户隔离均有验证记录。

**完成标准**：注册后可持会话访问受保护接口；退出后失效；用户数据隔离不依赖前端隐藏。

## 6. P3：模板 API、上传与文件读取

**产物位置**：`backend/src/main/java/.../template/`、`.../asset/`、`.../storage/` 及对应测试。

- [x] **P3-01 实现模板接口**：分类、按分类列表、详情全部从 Java／MySQL 获取；未找到详情返回 404，未知分类返回空列表；返回浏览器可访问的封面地址。
- [x] **P3-02 实现上传校验**：接收单图片 multipart，支持 JPEG／PNG、最大 5 MiB；同时校验字节大小、实际内容和可解码性，不信任扩展名或声明 MIME。
- [x] **P3-03 实现可靠存储**：服务端生成文件名，受控根目录保存；文件完整写入后才创建可用素材记录；失败时清理临时文件，不暴露任意路径读取接口。
- [x] **P3-04 返回素材 DTO**：包含 assetId、实际类型、大小和预览地址；确认浏览器刷新后仍可访问，不使用 blob URL 充当服务端素材地址。
- [x] **P3-05 实现受保护预览**：`GET /assets/{id}/content` 检查登录及归属，返回正确 Content-Type；模板封面公开读取；缺失文件和越权访问有明确响应。
- [x] **P3-06 对齐各层限制**：Java multipart 限制、Next.js 转发限制、超时及前端提示协议保持一致；验证边界大小、超大、伪装格式、损坏图片和空文件；页面提示本身在 P5 实施。
- [x] **P3-07 明确替换／移除语义**：上传接口不提供删除；前端移除的是引用，孤立文件清理属于已知限制；明确 P4 创建任务时再次检查全部素材及模板要求，交互在 P5 实施。

**完成标准**：真实图片从浏览器入口上传到数据卷，Java 能再次读取；非法上传失败可理解；用户之间不能读取素材。

## 7. P4：任务受理、分步执行、查询和重启

**产物位置**：`backend/src/main/java/.../task/`，内部区分 API、服务、Mapper、调度器、编排器、步骤和模拟配置；对应 `backend/src/test/` 测试。

### 7.1 创建与幂等

- [x] **P4-01 定义状态模型**：任务 `QUEUED/RUNNING/SUCCEEDED/FAILED`；阶段 `MATERIAL_CHECK/GENERATE/FINALIZE`；步骤 `PENDING/RUNNING/SUCCEEDED/FAILED`；确定等待、成功、失败各字段的空值与保留规则。
- [x] **P4-02 实现提交校验**：模板存在，素材数量准确、ID 不重复、归属正确、文件存在、类型和大小满足所选模板；客户端绕过校验仍不能提交非法任务。
- [x] **P4-03 实现短事务受理**：一次提交创建任务、素材顺序关联、三个 PENDING 步骤和配置快照；全部成功提交后返回 202 与任务 ID；创建失败不能留下可领取的半成品任务。
- [x] **P4-04 实现幂等**：同一用户的 requestId 与模板及有序 assetIds 对应；重试相同内容返回原任务，不同内容返回 409；并发唯一冲突在事务边界外正确处理，不形成重复任务。

### 7.2 领取与执行

- [x] **P4-05 实现单后台执行器**：独立于 HTTP 请求，按 createdAt、ID 领取最早任务；`UPDATE ... WHERE status=QUEUED` 成功后才能执行；同一时刻只执行一个任务，调度调用不得重入。
- [x] **P4-06 实现步骤编排**：素材检查 → 模拟生成 → 结果整理；每步开始先持久化阶段与 RUNNING，结束保存时间与结果；不能仅靠前端文案或一段总 sleep 模拟全部阶段。
- [x] **P4-07 实现素材检查步骤**：执行前再次读取素材与文件，检查数量及实际可用性；执行该步配置延迟与指定失败，失败后不调用后两步。
- [x] **P4-08 实现模拟生成步骤**：使用任务配置快照，延迟后选择模板预置图片；不调用真实 AI；素材检查失败时绝不能进入此步骤。
- [x] **P4-09 实现结果整理步骤**：保存为任务专属结果文件，确认可读取；同一事务更新最后步骤成功与任务成功、结果路径和完成时间；写入或校验失败不能标为成功。
- [x] **P4-10 实现失败终止**：阶段异常转为稳定错误码和可理解原因；任务和当前步骤失败，后续步骤保留 PENDING；P4 完成服务端状态，P5 提供页面“未执行”文案，P6-05 已通过专项验收；日志包含任务 ID 与阶段。
- [x] **P4-11 保护事务与终态**：延迟、文件操作不长期占有数据库事务；完成和失败更新附带预期状态条件；调度异常不能悄悄停止后续领取，不能在数据库写入失败时只在内存宣称成功。

### 7.3 模拟配置与重启

- [x] **P4-12 实现环境变量配置**：`SIM_CHECK_DELAY_MS=2000`、`SIM_GENERATE_DELAY_MS=8000`、`SIM_FINALIZE_DELAY_MS=2000`、`SIM_FAIL_STAGE=NONE`；支持三个指定失败阶段；负耗时或非法枚举启动时报错。

上面的 npm 和 Maven 命令在相应项目目录及容器内执行；CI 的实际脚本与此一致。镜像构建过程负责所需依赖安装，不要求评估者在宿主机执行这些命令。

## 14. 风险、缓冲与完成定义

### 14.1 需要优先消除的风险

| 风险 | 发现时点 | 处理 |
| --- | --- | --- |
| 镜像／依赖拉取或版本不兼容 | P0 | 尽早构建最小链路，锁定兼容版本，记录阻塞；不拖到收尾 |
| 同源代理丢失 Cookie、CSRF 或 multipart | P0、P2、P3 | 从真实浏览器入口验证，禁止只验证直连 Java |
| 文件只存在宿主机，容器中缺失 | P1、P3、P8 | 示例随构建打包，用户文件落卷，实际读取验证 |
| 事务未提交就执行、多个调度重入 | P4 | 数据库已提交队列、条件领取、单执行器、事务测试 |
| 登录成功但下次请求丢失认证 | P2 | 验证 SecurityContext 保存与会话 Cookie，做独立请求测试 |
| 轮询结束时未拿到终态 | P6 | 按 taskId 查询详情，active 消失不代表成功 |
| 默认重试和焦点重取造成无效请求 | P6、P7 | 明确配置策略，用假定时器和请求计数验证 |
| 暂时查询失败污染任务状态或用户缓存 | P6 | 分离错误类型、保留数据、取消和用户作用域校验 |
| 配置切换重启与指定阶段失败混淆 | P4、P9 | 先结束旧任务再改配置；两种失败分别记录 |
| 文档完成度超过实际验证 | P9 | 将实现、自动化、人工验证分别记录，未验证如实说明 |
