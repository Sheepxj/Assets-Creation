## 1. 目标与范围

实现可独立运行的素材制作网站。用户浏览模板，注册或登录，上传图片并提交制作任务；Java 在后台依次执行素材检查、模拟生成、结果整理；用户可继续浏览、连续提交任务，并在个人记录中查看进度、结果和失败原因。刷新页面后，系统从后端恢复记录并继续跟踪未完成任务。

### 1.1 已确认的关键决策

| 项目 | 决策 |
| --- | --- |
| 开发目标 | 一天内完成核心功能、关键测试、容器交付和文档 |
| 身份管理 | 支持用户名密码注册、登录、退出，注册成功自动登录 |
| 用户数据 | 素材和任务按用户隔离，Java 校验归属 |
| 后台任务 | MySQL 保存待执行任务，单个 Java 后台执行器按顺序领取 |
| 执行步骤 | 素材检查 → 模拟生成 → 结果整理 |
| 前端更新 | 轮询，只自动跟踪当前用户的未完成任务 |
| 服务重启 | 等待任务保留并继续处理；执行中任务标记为中断失败；终态任务保持不变 |
| 文件存储 | 后端本地目录，容器数据卷持久化 |
| 运行交付 | Docker Compose 启动 Next.js、Java、MySQL 三个服务 |

### 1.2 不在本次范围内

真实 AI 调用、视频处理、支付、模板管理后台、邮件或手机验证、密码找回、角色权限管理、任务取消、失败重试、重新制作、下载、删除、消息队列、Redis、SSE、WebSocket、多后端实例调度、执行中任务自动续跑、公网部署和复杂动效。

这些范围不影响题目要求的业务闭环。若后续增加，需另行评估时间和设计。

## 3. 架构与职责

浏览器通过 Next.js 提供的同源入口访问页面和 `/api/*`。Next.js 将业务请求转发到 Java，保留 Cookie、必要请求头和响应中的 Set-Cookie。上传体积限制及转发超时必须覆盖题目允许的文件，不把整个制作时长设为请求等待时间。

Java 内部分为认证、模板、素材、任务 API、任务调度和步骤执行模块。MyBatis 负责数据库访问。Next.js 不执行制作业务，也不直接写入 MySQL。

MySQL 是任务状态和个人记录的事实来源；前端状态和内存中的执行上下文均不能替代数据库记录。关闭页面、停止轮询和用户退出不应取消后台任务。

文件目录区分只读示例素材、用户上传素材和任务结果。容器重建后，用户文件及数据库记录通过数据卷保留。数据库中的地址采用同源相对 API 地址，避免将容器内部主机名暴露给浏览器。

部署边界为单个 Java 实例、单个工作执行器。增加并发或实例数量不属于本次目标。

## 4. 页面与用户流程

### 4.1 模板广场 `/`

从 Java 获取分类和模板列表，支持分类筛选。卡片显示标题、封面和简短说明，点击进入详情。提供加载、空列表及失败重试状态。

准备约六个模板，覆盖不同分类，以及需要一张、两张、三张图片的情况。模板数据来自数据库种子数据，不在前端写死。示例素材随项目交付，不依赖付费或内部服务。

### 4.2 模板详情 `/templates/[id]`

显示标题、描述、示例图片、图片数量、支持格式和大小限制。根据模板生成上传位，支持选择、预览、替换、移除及上传失败后重新上传。

未登录时可以查看详情，开始上传或制作前引导登录。素材未全部上传成功、校验未通过或提交请求进行中时，禁止提交。

任务受理后显示任务卡片及查看个人任务的入口，提交状态结束。用户可以重新选择素材并发起下一次制作。

### 4.3 我的任务 `/tasks`

按创建时间倒序展示当前用户的任务，包含模板信息、创建时间、整体状态、当前阶段、失败原因或成功结果。历史列表支持分页，自动跟踪逻辑不局限于当前分页。

等待中与执行中有不同反馈；执行中展示三步阶段信息，不展示无法由后端证明的精确百分比。成功结果可打开预览。模拟结果明确标注，使用项目自带示例图，不承诺真实合成上传图片。

导航可显示未完成任务数量。任务跟踪放在登录后的共享页面布局中，浏览列表、详情和历史页面时保持一致；离开相关布局后清理跟踪。

### 4.4 登录 `/login`、注册 `/register`

登录输入用户名和密码。注册输入用户名、密码和确认密码，注册成功自动登录。登录后返回原目标页面，返回地址仅允许站内路径。

所有表单有字段标签、键盘焦点和明确反馈。桌面为主要布局，小屏下能够完成所有操作。P0 已核实参考截图，后续对照主要布局，不以逐像素还原为目标；观察记录见 `docs/reference-ui.md`。

## 5. 身份认证与归属校验

- 用户名去除首尾空白并将英文字母转为小写，注册和登录使用同一规则；规范化后采用 3～32 位英文字母、数字和下划线，唯一性由数据库唯一约束保证。
- 密码至少 8 个字符，按照 BCrypt 的 72 字节输入上限校验 UTF-8 长度，不静默截断；确认密码由前端校验，后端仍独立校验密码规则。
- 数据库只保存 BCrypt 哈希，不记录明文密码。登录失败使用统一提示。
- 使用 Spring Security 处理认证、会话固定攻击防护和 CSRF 防护。前端通过同源接口获取 CSRF Token，在写请求及上传中提交。
- 登录、注册和退出改变认证状态后重新获取 CSRF Token。会话采用 30 分钟无操作过期。
- 会话 Cookie 使用 HttpOnly、SameSite=Lax；HTTPS 部署启用 Secure。本地 HTTP 容器演示使用与环境匹配的设置。
- 会话使用 Java 内存，不持久化到数据库；后端重启后重新登录，数据库中的用户及个人记录保留。
- 未登录的受保护 API 返回 JSON 401，由前端引导登录，不向 API 返回 HTML 登录页。
- 素材查询、文件读取、任务提交、任务查询和结果预览全部校验当前用户归属。对非本人资源返回 404，避免泄露资源信息。
- 会话过期只影响访问，不改变后台任务的执行状态。
- 初始化两个开发演示账号，并在 README 明确其演示用途，同时支持独立注册新账号。

## 6. 数据模型

| 表 | 主要字段与用途 |
| --- | --- |
| users | ID、规范化用户名、密码哈希、创建时间 |
| templates | ID、标题、分类、描述、封面地址、图片数量、允许格式、大小上限、预置结果路径 |
| assets | ID、用户 ID、原文件名、实际格式、大小、存储路径、创建时间 |
| tasks | ID、用户 ID、模板 ID、模板标题快照、整体状态、当前阶段、模拟配置快照、失败原因、结果路径、创建及执行时间、提交幂等键 |
| task_assets | 任务 ID、素材 ID、上传位顺序 |
| task_steps | 任务 ID、阶段、步骤状态、开始和结束时间、错误码及原因 |

约束与索引：

- users 的规范化用户名唯一。
- task_assets 的任务与上传位组合唯一；同一素材不能重复占据同一任务的多个位置。
- task_steps 的任务与阶段组合唯一。
- tasks 的用户与提交幂等键组合唯一。
- 为任务领取建立状态、创建时间和 ID 索引；为个人记录建立用户、创建时间和 ID 索引。
- 关联关系使用外键或等效约束维护，提交和执行阶段均校验实际文件存在。
- 时间按 UTC 保存，通过 ISO 8601 返回，前端按用户本地时间展示。

个人历史直接查询 tasks，不维护重复的历史表。结果文件、步骤和任务的关系可以由源码及数据库记录检查。

## 7. 上传与文件访问

第一版支持 JPEG、PNG，单文件上限为 5 MiB；模板可以使用该范围内更严格的要求。

前端做数量、声明格式及大小校验。后端检查大小、实际文件内容及图片可解码性，不仅依赖扩展名或客户端 Content-Type。存储文件使用服务端生成的名称，不将用户文件名拼接为存储路径。

上传成功后返回素材 ID 和受保护预览地址。浏览器临时地址仅用于本地即时预览，制作提交必须使用已经保存成功的服务端素材 ID。

上传素材及任务结果通过 Java 的受保护文件接口读取；模板封面可以公开读取。文件读取仅允许数据库记录指向的受控目录，不接受任意路径参数。

替换或移除上传位只改变当前表单引用；本次不提供远端文件删除及孤立文件自动清理。文件未完整写入时不创建可用素材记录，失败上传清理临时文件。

## 8. 任务状态与执行

### 8.1 整体状态

| 状态 | 含义 | 允许的后续状态 |
| --- | --- | --- |
| QUEUED | 已受理、等待后台领取 | RUNNING |
| RUNNING | 正在执行三个步骤 | SUCCEEDED、FAILED |
| SUCCEEDED | 结果已整理并可访问 | 无 |
| FAILED | 执行失败或重启中断 | 无 |

阶段使用 MATERIAL_CHECK、GENERATE、FINALIZE，分别表示素材检查、模拟生成、结果整理。等待中阶段为空；成功时保留 FINALIZE；失败时保留实际失败或中断阶段。

步骤状态使用 PENDING、RUNNING、SUCCEEDED、FAILED。失败后，后续步骤保留 PENDING，并由任务终态说明不会继续执行。

### 8.2 创建与领取

1. 校验登录身份、模板存在、素材归属、数量、重复素材、格式和大小。
2. 在短事务内创建 QUEUED 任务、素材关联和三个 PENDING 步骤，保存模拟配置快照。
3. 事务成功后返回 HTTP 202、任务 ID 和当前状态，不等待制作。
4. 后台执行器定时查找最早的 QUEUED 任务，按创建时间和 ID 排序。
5. 通过附带 QUEUED 条件的更新领取任务，在短事务内变为 RUNNING，然后执行步骤。
6. 单执行器一次处理一个任务；后续任务留在数据库，不依赖内存队列保存。

前端为一次明确的提交生成幂等键。请求异常后重试使用同一个键；后端对相同用户、相同键和相同提交内容返回原任务。相同键搭配不同内容返回冲突，不重复创建任务。

### 8.3 三步执行

| 阶段 | 行为 | 持久化边界 |
| --- | --- | --- |
| 素材检查 | 再次检查素材记录及文件可用性，执行可配置延迟或指定失败 | 当前阶段、步骤开始、成功或失败 |
| 模拟生成 | 执行可配置延迟，选择模板对应的预置生成结果或指定失败 | 当前阶段、步骤开始、成功或失败 |
| 结果整理 | 执行可配置延迟，将预置图片保存为任务结果，检查可读取性 | 结果路径、步骤结束、任务成功；或失败信息 |

开始步骤时先保存 RUNNING 状态；结束时保存该步结果，再进入下一步。延迟和文件操作在数据库事务外执行。正常完成最后一步时，在同一数据库事务中保存 FINALIZE 成功和任务 SUCCEEDED。

异常统一转换为可理解的错误码与原因，停止后续步骤，保存 FAILED。数据库更新附带预期状态条件，防止终态被后续回调或查询覆盖。

查询接口不创建执行器、不执行步骤、不推进状态。任务执行日志带任务 ID 与阶段，便于定位问题，不输出密码和会话值。

### 8.4 服务重启

启动时，在允许调度器领取新任务之前执行恢复检查：

- RUNNING 任务变为 FAILED，原因是“服务重启导致制作中断”，保留当前阶段；正在执行的步骤同步标记 FAILED。
- QUEUED 任务原样保留，随后继续领取，使用原来保存的模拟配置。
- SUCCEEDED 和 FAILED 保持不变。

本次不自动重试或续跑执行中的任务。正常关闭时停止领取新任务；无法在关闭窗口内完成的任务由下次启动按上述规则处理。

## 9. 可重复模拟

模拟配置通过后端环境变量提供，不加入普通用户的模板表单：

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| SIM_CHECK_DELAY_MS | 2000 | 素材检查延迟 |
| SIM_GENERATE_DELAY_MS | 8000 | 模拟生成延迟 |
| SIM_FINALIZE_DELAY_MS | 2000 | 结果整理延迟 |
| SIM_FAIL_STAGE | NONE | NONE、MATERIAL_CHECK、GENERATE、FINALIZE |

延迟必须为非负数，失败阶段值必须有效，配置不合法时启动失败并明确报错。创建任务时复制配置，执行时读取任务快照。

切换配置后重新创建后端容器，只影响以后创建的任务；已等待任务仍使用原配置，正在执行任务遵循重启中断规则。README 演示指定阶段失败时，先等待已有任务结束，避免把配置切换引发的中断误认为指定阶段失败。

不使用随机失败。测试中注入不真实等待的延迟实现，直接验证步骤与状态。

## 10. 前端异步状态与生命周期

前端分别管理四类状态，不能共用一个 loading 或 error：

| 类别 | 状态 |
| --- | --- |
| 上传 | 空、上传中、成功、失败 |
| 提交 | 空闲、提交中、受理成功、请求异常 |
| 任务 | QUEUED、RUNNING、SUCCEEDED、FAILED |
| 查询 | 正常、更新中、暂时不可用 |

- 查询缓存键包含当前用户 ID；单任务数据额外包含任务 ID。
- 登录后先读取未完成任务及历史，再恢复跟踪。未完成查询不受历史分页影响。
- 未完成接口用于发现待跟踪 ID；随后按任务 ID 查询详情，保证任务结束时能够获取最终结果或原因，不能仅凭它从未完成列表消失来推断成功。
- 有未完成任务时按约两秒间隔更新；任务进入终态后不再自动查询该任务。
- 最后一个未完成任务结束后，更新历史列表并停止自动轮询；此后新建任务会重新启动跟踪。
- 查询暂时失败时保留上一次任务状态、显示更新异常及手动恢复入口；暂停失败的自动跟踪，不将任务改为 FAILED。
- 离开相关布局、退出或切换账号时取消请求并清理用户缓存；利用请求取消和用户作用域校验避免旧响应覆盖新状态。
- 上传替换和移除后，旧请求的完成结果不能覆盖新的上传位。
- 提交异常无法确认是否受理时保留幂等键，允许恢复查询或安全重试。
- 页面卸载只清理前端资源，不发送后台取消请求。

## 11. API 契约

所有路径由 Java 实现，经同源 `/api` 入口访问。成功响应使用明确的 DTO；异常采用统一结构，包含 code、message、fieldErrors，无字段错误时为空对象。历史分页返回 items、page、pageSize、total；分类、模板和未完成任务直接返回数组。具体契约见 `docs/api.md`。

| 方法与路径 | 输入或输出要点 |
| --- | --- |
| GET /api/auth/csrf | 获取写请求所需 CSRF Token |
| POST /api/auth/register | username、password；创建用户并建立会话 |
| POST /api/auth/login | username、password；建立会话 |
| POST /api/auth/logout | 注销会话 |
| GET /api/auth/me | 当前用户 ID、用户名；未登录返回 401 |
| GET /api/templates/categories | 模板分类 |
| GET /api/templates | 可选 category；模板列表 |
| GET /api/templates/{id} | 模板详情与素材要求 |
| POST /api/assets | multipart 图片；返回素材 ID、格式、大小、预览地址 |
| GET /api/assets/{id}/content | 本人上传图片内容 |
| POST /api/tasks | templateId、按上传位排列的 assetIds、requestId；返回任务 ID 与状态 |
| GET /api/tasks | 本人历史，支持分页和状态筛选 |
| GET /api/tasks/active | 当前用户所有未完成任务 |
| GET /api/tasks/{id} | 状态、阶段、步骤记录、时间、结果地址或失败信息 |
| GET /api/tasks/{id}/result | 本人成功任务的结果图片 |

任务查询 DTO 至少包含 id、templateId、templateTitle、status、currentStage、steps、createdAt、startedAt、finishedAt、resultUrl、errorCode、errorMessage。

典型 HTTP 语义：400 参数错误，401 未登录，403 CSRF 校验失败，404 资源不存在或不属于本人，409 用户名或幂等提交冲突，413 文件过大，415 不支持的图片格式。预期的任务执行失败通过任务状态表达，不能与 HTTP 请求异常混淆。

## 12. 测试与验收

### 12.1 后端关键测试

1. 三个步骤严格按顺序执行，成功时结果可读取。
2. 分别指定三个阶段失败，验证失败阶段、原因，以及后续步骤没有执行。
3. 创建接口不等待任务完成，查询不会推进任务，终态不会回退。
4. 重复幂等请求只创建一个任务。
5. 启动恢复后 RUNNING 失败、QUEUED 可继续执行、终态不变。
6. 注册、密码哈希、登录，以及用户之间的素材和任务隔离。
7. 上传类型、大小、数量和不存在素材的服务端校验。

步骤编排测试使用可控制的步骤实现和延迟替身，不通过长时间 sleep 断言。数据库相关集成测试在容器或 CI 的 MySQL 服务中验证。

### 12.2 前端关键测试

1. 两个任务的阶段、失败和结果互不覆盖。
2. 查询异常保留已有信息，与任务 FAILED 明确区分。
3. 终态停止跟踪，无未完成任务时停止轮询。
4. 用户切换、卸载和旧响应返回后不污染当前数据。
5. 上传失败、未上传完及提交中不能错误提交。

不要求端到端测试和固定覆盖率，优先验证题目关心的实际行为。

### 12.3 人工演示顺序

注册并登录 → 分类切换 → 上传校验、预览、替换、移除 → 连续提交两个任务 → 观察排队及三个阶段 → 刷新后恢复 → 成功图片预览 → 切换用户验证隔离 → 分别演示指定阶段失败 → 暂停 Java 验证查询异常 → 重启验证排队保留与执行中断。

## 13. CI、容器与交付

- GitHub Actions 在 push 和 pull_request 触发，执行前端 lint、TypeScript 类型检查、构建，以及 Java 测试、打包。
- lint 显式执行，不依赖 Next.js 构建隐式检查。
- Compose 提供 MySQL 健康检查和依赖就绪处理，Java 完成数据库可用性及启动恢复后接受任务。
- 初次启动执行数据库结构和种子数据初始化；已有数据卷不会重复覆盖用户和任务。
- 示例素材在构建产物中可用，数据库及用户文件分别持久化；后端启动时检查存储目录可写。
- 配置示例不含真实密码或其他凭据；数据库端口不必向宿主机公开。
- 交付默认入口是 docker compose up --build，不要求评估者在宿主机安装 Node.js 或 Java。
- README 记录版本、结构、配置、初始化、启动、测试、接口、状态、身份、多任务、刷新恢复、模拟控制、重启边界和已知限制。
- README 如实填写完成项、未完成项、实际投入、AI 工作流、素材及复用来源，区分代码实现与实际运行验证。
- 部署说明包含构建、启动、健康检查、数据备份和验收 commit；回滚使用上一版本镜像或提交重建，保留数据卷，不假定代码回滚能够自动回滚数据库。

## 15. 时间安排与已知边界

一天时间按约 10% 用于设计和接口、30% 用于 Java 与数据库、30% 用于前端、30% 用于测试和容器联调及文档。测试、容器交付和题目必需功能优先于动效和装饰。

当前设计接受的边界：

- 单个 Java 实例和单执行器，任务排队而非并行。
- 执行中任务不自动续跑；重启后会话失效，需要重新登录。
- 结果为预置模拟图片，不真实合成用户图片。
- 不自动清理未引用上传文件，以及进程中断时可能留下的未关联结果文件。
- 身份方案面向笔试交付，不包含注册滥用治理或完整生产账号体系。
- P0 已读取参考截图，布局观察已记录；正式页面在 P5、P6 实现，不能将观察记录视为视觉还原已完成。
- 本文未声明任何应用测试、构建或运行已经通过，实际结果在开发完成后单独记录。

本文作为后续实现的范围基线。涉及新增功能、并发扩展或恢复语义的变更，应同步更新设计与 README，避免实现和验收说明不一致。
